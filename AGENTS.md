## Current user decision

v1 is on `main`: PRs #1–#9 were merged on 2026-10-23 and released as v1.0.0. The closed PR #3 draft is kept as the tag `archive/v1-slice1-coding-core`. Work on a branch and open a pull request to `main`; CI runs on every pull request and every push to `main`, and pushing a `v*` tag builds a release. Merging and tagging are the owner's decisions.

Connection hardening (`feat/v1-connect-hardening`) records user decisions: any https OAuth callback is accepted for the configured client (errors before the password stay on the local page), any requested scope is granted as `mcp`, a `resource` indicator never refuses, refresh tokens are kept rather than rotated and do not expire by default, NuGet audit findings stay warnings, and the tray and server start at sign-in from a Startup-folder shortcut with supervised restarts. Its availability pass adds: nothing optional stops the server (bad root entries are skipped, missing roots, overlapping roots and a state_dir inside a root are warnings; only the state lock, `TransportRefusal` and `NoAuthRefusal` refuse), configuration saves are atomic with `.bak` recovery, a damaged ledger is quarantined and rebuilt, browser mounts connect in the background and restart with backoff, the tray relaunches without a console and runs once per configuration, and CODEXish's own state is cleaned by age (`retention`, 30/90 days, a user decision). Its review pass deletes only files whose whole name is one CODEXish gives its files (never a directory), keeps an artifact row until its file is gone and a process row while its job holds descendants, recovers `codexish.json` without overwriting a newer save, skips malformed `allow_hosts`/`allow_origins` entries and treats JSON `null` as the default, makes event writes best-effort, and has the console relaunch wait, without a timeout, for the copy's ready event or its exit. Pass 4 adds RFC 7591 Dynamic Client Registration for ChatGPT Plugins next to the unchanged static client: a public `/register`, exact registered callbacks, PKCE for public clients, codes and tokens bound to their client, only anonymous never-signed-in registrations bounded (newest 1,000) and aged out, and removal only as the tray's or `/control/remove-clients` user action; client ID metadata documents must not be advertised until they are fully implemented, because a client that sees them offered skips registration. Do not reintroduce rotation, replay revocation, scope or resource refusals, audit findings as errors, startup refusals for optional settings, deletion of files CODEXish did not name, or any gate, cap, timeout or latch that can stop a working run.

## Local MCP parity decisions (2026-10-30)

Read `docs/local-mcp-parity-plan.md` revision 7 before editing this feature; its appendix fixes the model-facing strings verbatim. Scope B mirrors `mcp_servers`/`mcpServers` in `codexish.json` and each configured root's `.mcp.json`, never other agents' user-level files. Root-bound servers need read and shell to start/read and also write for changing tools; the shell grant is the trust decision, with no extra approval. An unbound global definition is the user's permission. Only explicit `read_only_tools`, never a backend hint, bypasses the invocation ledger.

Automatic stdio environment inheritance stays allowlisted; explicitly configured `env`, `env_vars` and header variables pass regardless of their names, including proxy settings. Preserve current-user environment refresh for children, additive secret redaction, literal-percent Windows batch quoting, and the documented post-start Job Object grandchild gap. Do not add suspended-start machinery for that gap.

Malformed definitions and reload files are isolated, never startup gates. Mount reload is read-only, preserves the last usable set on file errors, leaves unchanged servers alone and drains dispatched calls before replacing a changed server. Roots/grants and non-mount settings still apply at restart. Tray roots saves replace only `roots` in the current JSON and preserve unknown fields. Names are published together in deterministic precedence; collisions rename tools rather than dropping mounts.

No handshake or call deadline; supervision never gives up. Preserve the adaptive discovery/initialize handshake and last successful manifest mode, HTTP uncertainty rather than unsafe replay, resource paging and response-wait semantics, and shared-backend/conversation limitations. Commit-qualified local and CI results are recorded in IMPLEMENTATION_STATUS.md; revision-6 local and CI verification is recorded against its source, while revision-7 local Linux results identify the frozen working tree and its CI remains pending. Live Unity MCP acceptance from ChatGPT is separate and must never be inferred from fixture or cross-compilation results.

Revision 5 clarifications: a global name literally equal to a project identity overrides it, without rejecting slashes. Resource routing uses kind plus identity internally; `browser:<id>` addresses a browser and `mcp:<identity>` forces MCP after stripping exactly one prefix. Capabilities prefix an MCP identity beginning `browser:` or `mcp:` with `mcp:`. Rehash an occupied hash candidate with newline plus ordinal 2, 3, … until free. Reload compares the never-logged SHA-256 of canonical effective configuration, not raw text; saving identical text reevaluates expanded values, explicit environment and resolved command, without including the allowlisted base environment. SDK 2.2.0's HTTP 404 session expiry/cancellation is accepted without a DelegatingHandler. Unrequested cancellation is transport loss (changing `EXECUTION_UNKNOWN`, read-only `MCP_UNAVAILABLE`), not user `CANCELLED`, for stdio too.

Revision 6 review rules: isolate definition/file Unicode and schema failures, compare identities ordinal-ignore-case, tolerate comments/trailing commas/BOM at startup and reload. Additive redaction targets only the specified secret-bearing names/headers/query values of at least eight characters, never ordinary values globally. Decode result blocks from raw JSON and degrade unknown blocks to redacted text; only actual transport loss reconnects. Actual HTTP 404 is unavailable/effects none, while connection ambiguity remains unknown for changes. Resource listings are session-scoped, cancelled on retirement and never hold drains; resource envelopes never duplicate blobs. Capture file stamps before reading and re-fingerprint changed files only. Publish one complete snapshot without reader reload locks. Prepare duplicate-tolerant roots-save bytes before stopping and restart in finally. Capabilities display URL origin only plus `/…`, redact secret-flag values, retain browser stderr_tail and summary tool/source detail. Record every verification with its environment and source commit; earlier CI is not evidence for new review fixes.

Revision 7: publish global MCP/browser manifests before listen without environment/PATH/root I/O; project reads, fingerprints and starts stay background work. A completed session makes any call failure transport loss; a pre-dispatch failure sent nothing. Non-transport unreadable answers use the exact appendix A.7 text, not the protocol-error text. Failed file I/O drops only that stamp for next-pass retry without another save. Roots saves reread after stop and rebuild on a changed file; failure restarts without writing. Copy unused top-level values as raw JSON in load/save so malformed Unicode in unused fields does not block them. Browser variable expansion includes command as well as args.
