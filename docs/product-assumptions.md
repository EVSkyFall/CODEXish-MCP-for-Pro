# 제품 가정과 호환성

문서 기준일: 2026-09-15. **제품 가정, 공식 문서로 확인한 사실, 프로젝트 설계 결정, 실험으로 확인해야 할 사항을 구분한다.** 이 문서는 실제 계정에서 실행한 시험 보고서가 아니다.

## A-01. 사용자 입력 횟수 기반 제품 가정

사용자가 지정한 최상위 전제는 **“ChatGPT 공홈 Chat의 6 Pro는 토큰제 할당량이 아니라 사용자 입력 횟수제 할당량을 사용한다”**이다. 이에 따라 한 번의 사용자 입력 안에서 가능한 한 많은 도구 호출·관찰·수정·실행·테스트 반복을 수행해 Codex에 가까운 장시간 작업 루프를 구성한다.

이번에 확인한 공식 개발자 문서는 **6 Pro Chat의 구체적인 할당량 계산식**을 확정하지 않는다. 이 전제는 프로젝트의 방향을 정하는 사용자 제공 가정으로 유지한다. 다음을 덧붙여 사실처럼 쓰지 않는다.

- 사용자 입력 한 번의 정확한 비용, 하루·주간 입력 한도, 초기화 주기.
- MCP 도구 호출이나 승인·재시도·재생성이 할당량에 전혀 영향을 주지 않는다는 주장.
- 한 턴에서 가능한 도구 호출 횟수·추론 시간·문맥 크기와 무제한 작업 보장.
- API 모델과 Chat의 6 Pro가 같은 제품·가격·집계 체계라는 주장.

**설계상 결과:** 추가 입력을 요구하지 않아도 되는 관찰·수정·검증은 같은 작업 흐름에서 이어간다. 장기 작업 핸들, 증분 출력, journal, 재사용 가능한 허가를 제공한다. 결과의 정확성과 사용자의 중단 의사는 호출 수보다 우선한다.

## 이전 설계에서 정정한 부분

이전 대화의 설계를 현재 요청에 맞게 구조화했다. 참고 대화 조회에서 긴 응답 말미가 잘려 있었으므로, 이 문서는 그 응답 전체의 축어적 보존본이 아니다. 요청에 명시된 기능과 조회된 설계 내용을 바탕으로 작성했다.

| 이전 표현 또는 제안 | 이번 문서의 처리 |
| --- | --- |
| Pro는 read/fetch 전용이며 full MCP는 특정 조직 요금제만 가능하다. | 현재 읽은 공식 Developer mode 문서와 맞지 않아 제거한다. 계정별 실제 지원은 확인표로 관리한다. |
| 고정된 시간 제한·출력 크기·UI 노드 수를 기본 정책으로 둔다. | 확정하지 않는다. 응답 분할과 원본 artifact 접근을 정의하고 실제 전송 제약은 측정한다. |
| workspace·컴퓨터·탭에 작업 잠금을 둔다. | 유효 요청은 큐에 넣어 자동 시작하거나 동일 작업에 합류시킨다. 동시 실행 자체를 이유로 거절하지 않는다. |
| 임의 JavaScript를 `eval_readonly`로 제공한다. | 일반 스크립트의 읽기 전용성을 이름으로 보장하지 않는다. 고정 관찰 연산과 쓰기 가능한 실행을 분리한다. |
| 연결이 끊기면 긴 프로세스를 취소한다. | 전송 단절과 명시적 취소를 구별한다. 사전에 선택한 프로세스 수명 정책과 실제 상태에 따라 복구한다. |
| MCP 도구만 갖추면 Codex와 동등하다. | 실행 기능의 대응을 목표로 한다. Chat의 추론 지속·내부 harness·UI·사용량 체계는 복제 대상이 아니다. |

## 실계정 확인표

초기 상태는 모두 **미시험**이다. 시험자는 날짜, 제품 표면(Chat/Work/API), 계정 요금제, UI에 표시된 모델명, 관련 설정, 서버·Agent·프로토콜 버전, 증거 위치를 남긴다. 인증정보는 남기지 않는다.

| 시험 | 확인할 관찰 | 현재 상태 |
| --- | --- | --- |
| 연결 | 대상 계정에 Developer mode와 원격 MCP 연결이 표시되고 인증이 완료된다. | 미시험 |
| 6 Pro 선택 | 정확히 해당 모델을 선택한 Chat에서 도구 목록과 호출이 동작한다. | 미시험 |
| 읽기·이미지 | 파일 텍스트와 MCP image content를 모델이 받아 후속 판단에 사용한다. | 미시험 |
| 쓰기·승인 | disposable workspace의 변경, Chat 확인, 로컬 허가의 관계를 확인한다. | 미시험 |
| 같은 입력의 반복 | 추가 사용자 입력 없이 테스트 실패→수정→재검증을 이어가고 증거를 보고한다. | 미시험 |
| 긴 작업 | 실행 핸들 반환 후 증분 결과를 조회하며 실제 완료를 인식한다. | 미시험 |
| 승인 이후 | 사용자 승인 후 자동 진행 또는 다음 조회 중 어떤 경로로 결과를 받는지 확인한다. | 미시험 |
| 단절·재접속 | Chat 턴 종료, Gateway 단절, Agent 재시작을 따로 시험하고 재조회한다. | 미시험 |
| 사용량 표시 | 공식 UI에 노출된 표시만 관측한다. 표시가 없으면 미확인으로 남긴다. | 미시험 |

소수 실험의 성공이나 사용량 표시 변화만으로 비공개 집계 규칙을 역으로 확정하지 않는다. 기록은 해당 환경에서 관찰한 실행 능력의 증거이며 모든 계정·모델·미래 버전의 보장은 아니다.

## 변경 관리

제품 문서나 계정 동작이 달라지면 근거 날짜와 영향 범위를 수정한다. A-01의 설계 방향을 바꾸는 결정은 사용자와 확정한다. 코드 측 지원 여부는 요금제 이름을 하드코딩하는 대신 `host.capabilities`와 실제 연결 시험 결과로 표현한다.
